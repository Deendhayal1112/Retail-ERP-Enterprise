# Version 0.2 Development Notes — Retail ERP Enterprise

## 1. Objectives & Goals
The primary focus of **Version 0.2** is the creation of the **Enterprise Dashboard** and **Sales POS Register Foundation**. This transition expands the application from an authentication gate into a fully functioning, offline-first transactional application.

---

## 2. Completed v0.1 Modules (Frozen Base)
The following modules represent the stable `v0.1` architecture and must not be altered unless debugging critical system-level regressions:
- **Electron Shell Foundation**: Preload scripting context isolation, sandboxed IPC bridges, secure native window titlebars.
- **Secure Authentication Layer**: Local session lifecycle logic with rates-limited brute-force prevention and `bcryptjs` encryption.
- **Database Service Core**: SQLite instance connectivity operating via transactional WAL mode and robust foreign key constraints.
- **Design Tokens**: Standard light and dark mode colors maps implemented via responsive modern Tailwind CSS variables.

---

## 3. Upcoming v0.2 Modules (Target Scope)
Development in `v0.2` will introduce the following structures:
- **Enterprise Dashboard Layout**: Dynamic stats widgets displaying local sales metrics, inventory alerts, and user profiles.
- **Billing Register POS (Prototype)**: Checkout entry layout supporting receipt formatting templates and localized database transactions.
- **Access Control Panel**: Simple configuration tables showing assigned roles and specific access flags.

---

## 4. Architectural & Coding Decisions

### Security Guidelines
- **IPC Validations**: Every main-process handler must execute `validateSender(event)` to prevent untrusted render frames from invoking backend operations.
- **SQL Sanitization**: All queries must execute via prepared statements (`db.prepare().run()`) or built-in secure parameter bindings.
- **No Unsafe Evaluations**: Direct `eval()` or unsanitized DOM insertion (`innerHTML` templates) is strictly prohibited.

### Style & Layout Conventions
- **Pure JavaScript Rendering**: All presentation interfaces must execute using Vanilla JS DOM controllers. Avoid importing bloated React/Vue packages to ensure instant render metrics.
- **Tailwind Integration**: Build user layouts using Tailwind CSS utility flags mapped strictly against the design system guidelines defined in `src/renderer/styles/global.css`.

---

## 5. Development Workflow
To launch local development tasks:
```bash
# Set up environment variables
cp .env.example .env

# Install dependencies (auto-downloads correct SQLite prebuild)
npm install

# Start Electron and Tailwind CSS compilation watcher
npm run dev
```
